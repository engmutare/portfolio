Engineering software

Eletai

An engineering diagnostic platform from AMI Engineering that turns field measurements and equipment observations into structured evidence and traceable findings. It is built to help engineers model physical systems, run calculations and investigate faults. Its core idea is an application where calculations, components, dependencies and results have explicit relationships, so a changed input can mark dependent results as stale.

C++Qt 6Windows desktopdomain-oriented calculation core
Case study
Problem
Engineers often hold the model in one tool, the calculations in another and the reasoning in documents, so it is hard to tell which result depends on which assumption.
Design decisions
Domain logic is separated from presentation. Results are structured. Parameter dependencies and stale-result tracking are explicit.
Work areas
Native Windows app in Qt 6 and C++, electrical-system diagrams and component modelling, calculation workflows, and early work on linking local tools to cloud services.
Status
Ongoing product development.
Not claimed
Eletai is not presented as a replacement for established electrical packages or as suitable for safety-critical use.

Computer vision
Robotics / ML

BMW X5 lane-following simulation

Bachelor thesis: a simulated BMW X5 in Webots that follows a lane using classical computer vision and a U-Net segmentation approach.

Webotsclassical CVU-Netimage segmentation
Case study
Problem
Recover lane information from camera images, then turn it into steering commands.
Approach
Classical image processing and a U-Net model each produce lane information. Perception feeds the vehicle controller in the simulation.
Reported results
IoU of about 82.5% and Dice score of about 90.3%.
What they measure
IoU is the overlap between predicted and true lane pixels divided by their union. Dice is twice the overlap divided by the total of both areas. Both score segmentation quality only.
Limits
These metrics do not measure driving or control performance. This was a simulation, not a real-road or deployed system.

C++ engineering computation

Deterministic electrical calculations with explicit input and output contracts, developed in C++ as part of Eletai. Fixed assumptions and units make each result reproducible and open to challenge.

C++numerical computation
Worked example

This is a basic resistive case. Real systems add reactance, temperature, cable length and loading. Stating the assumptions and units with every result lets another engineer reproduce and challenge it, and a fixed expected value makes a regression test possible.

Distributed systems / ML

Anolix

A business intelligence and workflow product from AMI Software, aimed at extracting useful insight from business data. It explores a data-processing architecture built from independent components that work together as one system: event streaming, containerised services, machine learning and orchestrated workflows, rather than a single monolithic application.

DockerApache KafkaApache Airflowmachine learning
Case study
Problem
Business data arrives continuously from several sources, and turning it into operational insight needs more than one script.
Architecture
Docker packages the services and deployment environments. Kafka carries events between components. Airflow orchestrates and manages the processing pipelines. Machine-learning methods find patterns in the data.
Engineering focus
Working across layers, from infrastructure and event-driven communication to analytical processing and orchestrated workflows.
Scope
An architecture exploration. No metrics or production deployments are claimed.

How I approach a problem

Good engineering software is explainable, testable and honest about its limits.

Step 1

Understand the system

Components, interfaces, constraints, inputs, outputs and the physical behaviour that matters.

Step 2

Model the problem

Equations, algorithms, data structures, diagrams or simulation, whichever fits.

Step 3

Implement and verify

Build it, test key behaviours and edge cases, and compare against expected results.

Step 4

Communicate the result

Make assumptions, limits, calculations and conclusions clear to other engineers.
